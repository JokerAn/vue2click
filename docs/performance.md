# 性能检查记录

2026-10-09 对全部五个运行时源文件、扩展入口、打包方式和测试进行检查。本项目不使用寻路算法；采用的工程思路是共享预处理、按需计算、缓存／记忆化，以及合并进行中的重复请求（singleflight）。

原实现已经按文档 URI 和版本缓存整个文件的脚本索引，因此同一版本的每次点击并不会重新解析整个文件。主要可避免的开销是首次查询或文档修改后，提前为全部模板表达式创建语法树；其次是同一次跨文件查询的不同导出分支重复读取相同配置、探测相同文件。

本轮改动：

- 模板收集阶段只保留表达式范围和作用域；点击某个表达式时才解码 HTML 实体、建立偏移映射并解析表达式。相同文档版本中，解码内容和语法包装相同的表达式共享 AST，每个出现位置仍有独立的源码偏移和模板作用域。
- 单次跨文件请求共享文件读取、存在性检查、模块路径结果和已加载的文档索引；相同的进行中模块解析及文档打开共享 Promise。共享的读取不携带调用者的取消状态，各请求独立检查取消和所有已读文档的版本。
- 路径和文件存在性结果不会永久保存。操作完成后删除进行中的 Promise，下一请求重新创建读取 session，文件新增、移除或配置修改可被重新识别。
- 文件索引按最近使用顺序淘汰，最多保留 32 个文档及 400 万源码字符。文档修改重建索引，关闭文档删除索引。源码字符限制是缓存容量约束，不是实际内存上限。
- 保留配置继承和组件导出链的深度／总访问预算，避免循环及重复分支无界展开。

本机 Node 测量默认每个场景构建 7 次、本地查询 800 次、跨文件查询 60 次。构建样本已预热解析器，包含全新文件索引，不包含模块启动；跨文件场景使用已缓存的子组件索引，记录真实 `readFile` / `stat` 尝试，包含缺失配置探测。

| 场景 | 优化前／独立读取 | 优化后／请求内复用 |
| --- | ---: | ---: |
| 3,000 个重复模板表达式，构建中位耗时 | 13.558 ms | 6.311 ms |
| 同场景构建样本 p95 | 20.335 ms | 13.817 ms |
| 别名和中转导出，60 次跨文件查询总耗时 | 26.567 ms | 16.450 ms |
| 同跨文件场景读取尝试 | 600 次 | 360 次 |
| 同跨文件场景文件探测 | 720 次 | 480 次 |

跨文件的两种策略在同一次最终基准运行中对照，每次查询都重新创建 resolver/session，仅当前导出图内共享 IO。以上结果不包含扩展层的并发请求合并收益。

真实 `apply/index.vue` 优化前后构建中位数分别为 17.063 ms 和 17.342 ms，未显示稳定改善。真实 `process/index.vue` 在测量期间被外部编辑，前后文件大小不同，不用它宣称构建加速。优化后真实 `gotoPage(1)` 的 800 次已索引查询总耗时约 8.767 ms；`addressParams` 的 800 次查询约 4.963 ms。真实文件中脚本解析占主要构建成本，按需模板解析的收益小于大量重复模板的合成场景。

这些数字用于判断开销量级，不作为统计显著性或每台机器的性能保证。7 个构建样本的 p95 是描述性最近秩统计，样本较少。没有为目前单次微秒量级的成员扫描增加复杂索引，也没有引入跨请求永久路径缓存；避免因小收益扩大维护成本或产生过期定义。

复现命令：

```sh
npm run benchmark
npm run benchmark -- --json
BENCH_PROJECT_ROOT=/path/to/apply-claim npm run benchmark
```

原始业务项目不存在时自动使用合成文件。可通过 `BENCH_BUILD_RUNS`、`BENCH_WARM_CALLS`、`BENCH_CROSS_CALLS`、`BENCH_EXPRESSIONS` 调整样本规模，脚本限制每个测量批次的时间。计时不包含 VS Code UI、其他语言插件或扩展启动；并发合并和索引淘汰通过操作计数及正确性测试验证。

测试额外覆盖：按需解析、相同表达式共享 AST、模板局部变量和偏移独立、文档新版本不复用旧表达式、不同导入共享一次配置读取、同步异常与异步读取失败、取消独立、失败后的重新查询、缓存淘汰后重建，以及重复导出分支只打开一次共同子组件。
